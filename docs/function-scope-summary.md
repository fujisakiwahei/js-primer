# JavaScript 関数とスコープ まとめ

---

## 1. スコープとは

スコープとは、変数や関数を参照できる範囲のこと。関数を定義するたびに新しいスコープが作られ、その中で宣言した変数は外側からアクセスできない。仮引数も同様にその関数のスコープに属する。`let`/`const` では同じスコープ内に同名の変数を二重定義できないが、異なるスコープであれば同名の変数を定義できる。

### ひとことで言うと

**スコープ＝「変数がどこから見えるか」のルール**です。関数やブロック`{}`を書くたびに、新しい「部屋」ができて、その中で作った変数は外からは見えません。

---

**3つのスコープ**を押さえれば大枠はOKです。

**グローバルスコープ** — プログラム全体の一番外側。ここに置いた変数はどこからでも見える。便利だけど名前衝突しやすいので最小限にしたい。

**関数スコープ** — 関数の中で宣言した変数は、その関数の中だけで有効。外から触れない。

**ブロックスコープ** — `if`や`for`の`{}`の中で`let`/`const`で宣言した変数は、そのブロック内だけで有効。

---

**スコープチェーン**は、変数を探すときの「内→外」の探索ルールです。今いるスコープに変数がなければ、一つ外側、さらに外側…と辿っていき、どこにもなければ`ReferenceError`になります。

---

**varの巻き上げ**は古い仕組みで、宣言だけがスコープの先頭に引き上げられるため、宣言前でも`undefined`で参照できてしまいます。しかもブロックスコープを無視して関数スコープに属します。`let`/`const`ならこの問題は起きないので、基本は`let`/`const`を使えばOKです。

---

**クロージャー**は、内側の関数が外側の変数を参照し続けることで、関数が「状態」を持てる仕組みです。カウンターの例がわかりやすくて、`createCounter()`を呼ぶたびに独立した`count`変数が生まれ、返された関数がそれを保持し続けます。これは「静的スコープ（参照先がコードの位置で決まる）」と「参照が残っていればデータは解放されない（ガベージコレクション）」という2つの性質の組み合わせで成り立っています。

---

まとめると、この章の流れは **スコープの基本 → スコープチェーン → varの落とし穴 → クロージャー** という構成で、最終的に「関数は処理をまとめるだけでなく、変数の見える範囲を制御し、状態すら持てる」というところに着地します。

## 2. ブロックスコープ

`{}` で囲んだ範囲（ブロック）もスコープを作る。`if` や `while`、`for` のブロック内で `let`/`const` で宣言した変数は、そのブロック内でのみ有効。`for` 文ではループのたびに新しいブロックスコープが生成されるため、`const` でループ変数を定義してもエラーにならない。

## 3. スコープチェーン

スコープはネスト（入れ子）できる。変数を参照するとき、現在のスコープ → 一つ外側 → さらに外側…と順に探索し、見つかった時点でその変数を参照する。どこにも見つからなければ `ReferenceError` が発生する。内側と外側に同名の変数がある場合は、内側（より近い方）が優先される。

## 4. グローバルスコープ

プログラムの最も外側にある暗黙的なスコープ。ここで定義した変数（グローバル変数）はどのスコープからでも参照できる。`Array` や `isNaN` などのビルトインオブジェクトもグローバルスコープに存在する。グローバル変数がビルトインオブジェクトと同名の場合、グローバル変数が優先されてビルトインを隠蔽（シャドウイング）してしまう。対策として、むやみにグローバルスコープへ変数を定義せず、関数などで小さなスコープに閉じ込めるのがよい。

## 5. 関数スコープと var の巻き上げ

`var` で宣言した変数は、宣言部分だけがその関数（またはグローバル）スコープの先頭に巻き上げ（hoisting）される。そのため、宣言前に参照しても `ReferenceError` にならず `undefined` になる。さらに `var` はブロックスコープを無視し、最も近い関数スコープに属する。一方 `let`/`const` は宣言前に参照すると `ReferenceError` になり（TDZ）、ブロックスコープも正しく機能する。基本的に `var` は使わず `let`/`const` を使えばこの問題は回避できる。

## 6. 関数宣言と巻き上げ

`function` キーワードによる関数宣言は、宣言そのものが丸ごと巻き上げられるため、宣言前に呼び出しても正常に動作する。ただし `var hello = function() {...}` のように関数式を `var` に代入した場合は、`var` のルールで変数だけが巻き上げられ、値は `undefined` になるため呼び出せない。

### 即時実行関数（IIFE）

`var` しかなかった ES5 以前では、グローバルスコープの汚染を防ぐために `(function() { ... })()` という即時実行関数が使われていた。ES2015 以降は `let`/`const` とブロックスコープで代替できるため、基本的に不要。

## 7. クロージャー

クロージャーとは、関数が外側のスコープにある変数への参照を保持し続けられる性質のこと。これにより関数が「状態」を持てる。

### 背景となる2つの仕組み

- **静的スコープ**: 変数の参照先は、関数が定義された位置で静的に決まる（呼び出し元ではない）。
- **メモリ管理（ガベージコレクション）**: どこかから参照され続けているデータは解放されない。

### 動作の仕組み

`createCounter` のような関数が内部で `count` 変数を定義し、それを参照する `increment` 関数を返す。返された関数は `count` への参照を保持し続けるため、呼び出すたびに値が増える。`createCounter` を複数回呼べば、それぞれ独立した `count` を持つ関数が生成される。

### 主な用途

- 関数に状態を持たせる
- 外からアクセスできないプライベート変数を作る
- グローバル変数を減らす
- 高階関数と組み合わせて柔軟な関数を生成する

## 8. 全体のまとめ

| 概念               | ポイント                                                      |
| ------------------ | ------------------------------------------------------------- |
| スコープ           | 変数の参照可能範囲。関数・ブロックごとに作られる              |
| スコープチェーン   | 内側→外側へ順に変数を探す仕組み                               |
| グローバルスコープ | 最外のスコープ。変数を置きすぎない                            |
| var の巻き上げ     | 宣言が先頭に移動、ブロックスコープ無視。let/const で回避      |
| 関数宣言の巻き上げ | 関数ごと巻き上がるので宣言前に呼べる                          |
| クロージャー       | 静的スコープ＋GC により、関数が外側の変数を保持し状態を持てる |
